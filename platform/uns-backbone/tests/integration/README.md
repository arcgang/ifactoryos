# UNS Backbone — mTLS End-to-End Integration Tests

**Component:** `cmp:uns-backbone`  |  **Realises:** US-027 · BR-10  
**IEC 62443 SL2 audit evidence:** See *Audit evidence* section below.

---

## What these tests prove

| Test | Acceptance criterion |
|------|----------------------|
| `TestValidSvidAccepted` | MQTT CONNACK 0, QoS 1 PUBACK, and Kafka ACK for a valid SPIFFE SVID client; no rejection blob in WORM |
| `TestNoCertificateRejected` | No-certificate client rejected **within 100 ms**; audit blob in WORM **within 1 s** with `rejection_reason=no_cert_presented` |
| `TestUntrustedCaRejected` | Untrusted-CA certificate rejected **within 100 ms**; audit blob in WORM **within 1 s** with `rejection_reason=unknown_ca` |
| `TestCrossZonePublishDenied` | Gateway `body/01` can publish to its own zone; publishing to `paint/#` is denied |

The 100 ms and 1 s deadlines are **hard assertions** — they are not retried until they softly pass.

## Prerequisites

### Kubernetes test namespace

A namespace named `uns-backbone-test` must exist with the following deployed:

| Service | Helm chart / image |
|---------|--------------------|
| HiveMQ Enterprise | `hivemq-operator` 0.9.0 with `hivemq-values.yaml` |

| Azurite | `mcr.microsoft.com/azure-storage/azurite:3` |

The HiveMQ trust store must be loaded with the **test CA certificate** generated by
`fixtures/generate_test_ca.py` (see *Local setup* below).

Copy `fixtures/.env.example` to `fixtures/.env` and fill in the values:

```bash

   platform/uns-backbone/tests/integration/fixtures/.env

```

All secrets are read from environment variables or Vault; never hardcode credentials.

## Local setup

### 1. Generate the test PKI

```bash
cd platform/uns-backbone/tests/integration/fixtures
pip install cryptography
python generate_test_ca.py --out-dir ./pki
```

This writes:
- `pki/ca.pem` — test CA certificate (load into HiveMQ trust store)
- `pki/server.pem` — HiveMQ server leaf certificate
- `pki/server.key.pem` — HiveMQ server private key (**never commit**)
- `pki/edge-body-01.pem` / `pki/edge-paint-01.pem` — per-gateway SVID examples

### 2. Load the test CA into HiveMQ

```bash
# Example: update the hivemq-tls-truststore Kubernetes Secret
kubectl -n uns-backbone-test create secret generic hivemq-tls-truststore \
  --from-file=truststore.pem=pki/ca.pem \
  --dry-run=client -o yaml | kubectl apply -f -
```

### 3. Install Python dependencies

```bash
pip install -r platform/uns-backbone/tests/integration/requirements.txt
```

### 4. Run the tests

```bash
export $(grep -v '^#' platform/uns-backbone/tests/integration/fixtures/.env | xargs)

pytest platform/uns-backbone/tests/integration/test_mtls_e2e.py \
  -v -m integration
```

To skip integration tests in a unit-only run:

```bash
pytest -m "not integration"
```

## IEC 62443 SL2 audit evidence

> **The CI test run log for these four tests, together with the Terraform plan output
> from the HiveMQ and Kafka deployment in `platform/uns-backbone/main.tf`, constitutes
> the primary technical evidence presented to the external auditor for IEC 62443 SL2
> acceptance criterion US-027.**

To extract the CI artefact:

1. Open the GitHub Actions run for the branch under review.
2. Navigate to the `uns-backbone-integration-tests` job.
3. Download the `pytest-results` artefact (JUnit XML + stdout log).
4. Attach the log and the Terraform plan output to the audit package in Confluence
   under `IEC 62443 SL2 Audit Evidence / US-027`.

The auditor must see:
- Zero failures across all four test classes.
- `elapsed_ms < 100` logged for tests (b) and (c).
- WORM blob path and `rejection_reason` in the test output for tests (b) and (c).
- CONNACK `0x00` and PUBACK receipt logged for test (a).

## SPIFFE SVID URI format

Edge gateway principals follow the path:

```
spiffe://munich.bmw/edge-gateways/{shop}/{index}
```

Examples: `spiffe://munich.bmw/edge-gateways/body/01`,
`spiffe://munich.bmw/edge-gateways/paint/01`.

This matches the ACL rules in `platform/uns-backbone/helm/mqtt-acl-rules.xml` and the
trust domain registered in `platform/spiffe-spire/main.tf`.  The SVID path format is
recorded as an assumption on the pull request (resolved decision in the task board).
